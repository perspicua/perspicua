Perspicua Review Findings (non-kernel code)
===========================================

Findings from the November 2026 review of everything that is NOT the core
kernel: kernel/tests/, libc/, user/, uapi/, scripts/, the CMake files, the
justfile and CI. Reviewed at commit 499d800 (dev). Line numbers are from that
commit; if a file has moved on, search for the quoted text instead.

This file is a work list. Each item says what is wrong, exactly what to change,
and how to prove the change works. Take ONE item at a time.

--------------------------------------------------------------------------------
RULES FOR WHOEVER FIXES THESE
--------------------------------------------------------------------------------
  - One item per change. Stop after each so it can be committed on its own.
  - Do not commit, push, stage, or open PRs. The owner handles git.
  - Builds and boots go only in your own tree, never build/ or build-test/:
        just test_build_dir=build-test/fix test
        just test_build_dir=build-test/fix cmake_args="-DCONFIG_SMP=OFF" test
    Never run `just build`: it publishes to pi4-boot/.
  - Run `just check-format` before handing a change back.
  - Comments: almost none, one line at most, stating the rule the code keeps.
    Never describe the bug or its history in a comment.
  - -Werror is on. No floating point or SIMD anywhere. AArch64 only.
  - A change to a test must be shown to FAIL when the thing it tests is broken.
    Each item below gives the mutation to try. Apply it in a scratch git
    worktree, run the suite, confirm the failure, then discard the worktree.
    Never apply a mutation in the main tree.
  - Items marked NEEDS OWNER DECISION must not be started without an answer.
  - Do not touch kernel/{arch,core,mm,sched,fs,driver,devicetree,init} unless
    the item says so. Kernel bugs are listed at the end for the owner.

SUITE COUNTS. scripts/run_tests.sh holds a minimum test count per suite
(KERNEL_SUITES, USER_SUITES). When you add asserts, read the new count from the
suite's "N tests [OK]" or "all N tests passed" line and raise the minimum to
it. The script's own rule is "never lower one to pass". Three items below
remove redundant asserts and so lower a count on purpose; they are marked and
need the owner's go-ahead.

How each finding was confirmed:
  [RUN]    confirmed by running something (a mutation, a probe, or a command)
  [READ]   confirmed by reading the code; not run
  [UNSURE] plausible from reading; not confirmed

F01  [DONE] kernel/tests/test_sd.c:42-65   fake test   [RUN]
     The first half of the SD suite (read block 0, reread, zero-block read,
     two-block read) is answered by the block cache, not the SD driver. Mount
     already read the boot sector, so block 0 is cached before the suite runs.
     dev->read_blocks is the cached wrapper (kernel/driver/block.c:197).
     Evidence: a counter in sd_read_blocks showed ONE driver read across the
     four calls in that section (block 1 of the two-block read).
     Fix:
       - Call block_cache_invalidate() immediately before each of the three
         reads at lines 42, 50 and 64, so each one reaches the card.
       - The zero-block read (line 56) never reaches the driver through the
         wrapper and cannot. Keep it as a wrapper check, but replace the loop
         of 512 TEST_ASSERTs (lines 57-59) with one flag and one assert.
       - Fix the stale comment at lines 67-72: a failing TEST_ASSERT does not
         return from the suite. Say only that the block is restored first.
       - Line 22 dereferences dev after the NULL assert on line 21. Wrap the
         rest of the suite in `if (dev) { ... }` or return after
         TEST_SUITE_END when dev is NULL.
     Count: "SD Driver" drops from 545 to 34.  NEEDS OWNER DECISION (lowers a
     minimum on purpose).
     Prove it: in a worktree make sd_read_blocks XOR the first byte of the
     buffer when start_block == 0 and a test-only flag is set by test_sd just
     before line 42. "boot sig" or "reads are consistent" must now fail.

F02  [DONE] user/apps/test_syscall.c:94-114   fake test   [RUN]
     The gettimeofday and CLOCK_REALTIME checks pass when the kernel writes
     nothing at all: the struct is memset to 0 and the asserts are ">= 0".
     Evidence: with both handlers returning 0 without copying out, test_syscall
     still passed 187 of 187.
     Fix, for gettimeofday, CLOCK_MONOTONIC and CLOCK_REALTIME alike:
       - Start each struct at a sentinel the kernel can never return, e.g.
             struct timeval tv = {.tv_sec = -1, .tv_usec = -1};
         then keep the existing range checks. A call that writes nothing now
         fails them.
       - Add one check per clock that time moves: read, usleep(20 * 1000),
         read again, CHECK the second is later than the first.
     Count: test_syscall grows by 3; raise its minimum.
     Prove it: in a worktree delete the copy_to_user in gettimeofday_handler
     (kernel/core/syscall.c:457). The suite must fail.

F03  [DONE] user/apps/test_syscall.c:842-843   fake test   [RUN]
     Both mmap length checks pass flags 0 and fd -1, so the call fails with
     EBADF ("neither file nor anonymous") before the length matters.
     Evidence: with the kernel's length check removed the suite passed, and a
     probe printed errno 9 (EBADF) for both lines.
     Fix: make the length the only thing wrong and pin the errno:
             errno = 0;
             CHECK(mmap(NULL, 0, PROT_READ | PROT_WRITE,
                        MAP_ANONYMOUS | MAP_PRIVATE, -1, 0) == MAP_FAILED
                   && errno == EINVAL);
             errno = 0;
             CHECK(mmap(NULL, (size_t)1 << 40, PROT_READ | PROT_WRITE,
                        MAP_ANONYMOUS | MAP_PRIVATE, -1, 0) == MAP_FAILED
                   && errno == EINVAL);
       The kernel's cap is 256 MiB (SYSCALL_MAX_MMAP_SIZE), so 1 << 40 is past
       it.
     Count: unchanged.
     Prove it: in a worktree remove the `length == 0 || length > ...` check at
     the top of mmap_handler (kernel/core/syscall.c:1420). The suite must fail.

F04  [DONE] user/apps/test_libc.c:312-327   fake test   [RUN]
     test_malloc_coalesce only asserts `big != NULL`, which is true whether or
     not free() coalesces.
     Evidence: with coalesce() never called, test_libc passed 426 of 426 and
     stress passed 1290 of 1290.
     Fix: replace the body with a check that only a merged block can satisfy.
     This exact shape was validated on the host against libc/user/malloc.c: it
     passes with coalescing and fails without.
             char *a = malloc(256), *b = malloc(256), *c = malloc(256);
             char *guard = malloc(256);
             CHECK(a && b && c && guard);
             free(a);
             free(b);
             free(c);
             char *big = malloc(700);
             CHECK(big != NULL && big < guard);
             free(big);
             free(guard);
       Why it works: no single 256-byte hole fits 700, so without merging the
       request is served from the free tail above guard.
     Count: unchanged (still two checks).
     Prove it: in a worktree change `coalesce();` in free()
     (libc/user/malloc.c:122) to `(void)coalesce;`. test_libc must fail.

F05  [DONE] libc/kernel/panic.c:86-89   bug   [READ]
     The trap-frame register dump prints x0-x27, then x29 and x30. x28 is never
     printed: the loop stops at `i < 28`.
     Fix: run the loop to 30 so the last pair is x28/x29, and print x30 alone:
             for (int i = 0; i < 30; i += 2) { ...unchanged body... }
             panic_printf("  x30: 0x%016lx\n", tf->x30);
     Check: `just crash_build_dir=build-test/fix-crash crash-test` must still
     PASS. Its expected patterns do not include register lines.

F06  [DONE] libc/src/printf.c:364-365   bug   [RUN]
     "%#05o" (the '#' and '0' flags together on octal, no precision) loses its
     zero padding: 15 prints as "  017" where C requires "00017". The code
     implements '#' by raising the precision, and a precision turns the '0'
     flag off.
     Evidence: libc/src built on the host and compared with the host libc over
     479,663 cases. 133 differed, every one of the form %#0<width><len>o.
     strtol, strtoul, the mem* and str* functions, qsort and ctype all matched.
     Fix: put the leading zero in as a digit instead. Replace the body of that
     `else if` (the line `prec = num_len + 1;`) with:
             for (int i = num_len; i > 0; i--) {
                 num_buf[i] = num_buf[i - 1];
             }
             num_buf[0] = '0';
             num_len++;
       Leave the condition as it is. This exact change was run through the
       same comparison: all 133 differences disappear and nothing else moves.
     Add to test_snprintf_hash in user/apps/test_libc.c:
             snprintf(b, sizeof(b), "%#05o|%#5o|%#.2o", 15, 15, 15);
             CHECK(formats(b, "00017|  017|017"));
     Count: test_libc grows by 1; raise its minimum.

F07  [DONE] libc/user/syscall.c:222-240   bug   [READ]   NEEDS OWNER DECISION
     read, write, pread and pwrite with a length over 4 MiB fail outright with
     EINVAL. POSIX expects a short transfer. The kernel refuses the length
     rather than clamping it (kernel/core/syscall.c:111 and :138,
     SYSCALL_MAX_RW_SIZE in kernel/include/core/syscall.h:12). fread and fwrite
     inherit the failure for large buffers.
     Options:
       (a) libc clamps the length in those four wrappers. The cap then has to
           be visible to libc: move SYSCALL_MAX_RW_SIZE into a uapi/ header
           and include it from kernel/include/core/syscall.h.
       (b) the kernel clamps instead of refusing. test_syscall_bounds.c:150
           ("illegal_lens") expects a refusal for cap + 1 and would have to
           change.
     Either way add a userspace test: write a 5 MiB buffer to a scratch file
     and check the call returns a positive count no larger than the cap.

F09  [DONE] scripts/gdb_helpers.py   bug   [READ]
     The script has drifted from the kernel's data structures:
       - line 13: PROCESS_TABLE_SIZE = 1024. The kernel's is
         CONFIG_MAX_PROCESSES, default 128, so `ps` reads past the table.
       - process_table holds POINTERS and a free slot is NULL
         (kernel/include/sched/process.h:102). The script treats entries as
         structs with state 0 meaning empty.
       - PROCESS_STATE_NAMES: the kernel's states start at RUNNING = 1; there
         is no EMPTY.
       - TASK_STATE_NAMES: the kernel has RUNNING, READY, BLOCKED, STOPPED,
         DEAD (kernel/include/sched/sched.h:42). STOPPED is missing and DEAD
         is off by one.
       - line 65 reads `sched_core_pid`, which no longer exists.
       - the queue walks follow t["next"]; struct task links its run queue
         through rq_next. Check the sleep-queue link name the same way.
     Fix: derive the table size from the symbol
     (sizeof(process_table) / sizeof(process_table[0]) via gdb.parse_and_eval),
     skip NULL slots and dereference the rest, correct both name tables, and
     update the symbol and field names to what kernel/sched/sched.c and the two
     headers define today.
     Check: by hand. `just debug` in one terminal, `just gdb` in another, then
     run `ps` and `tasks`. No automated test covers this file.

F10  [DONE] kernel/tests/test_vfs.c:272, :59, :146 and test_fat32.c:254   bug   [READ]
     Four leaks inside the tests themselves:
       - test_vfs.c:272  `vfs_open(f, O_RDONLY) >= 0` is asserted and the fd is
         never closed. Pid 0 keeps it for the rest of boot, and the file is
         then unlinked while still open.
         Fix: store the fd, assert on it, vfs_close it when >= 0.
       - test_vfs.c:59 and :146  vfs_resolve_path returns a held reference
         (kernel/fs/vfs.c takes one before returning). Neither `root` nor
         `dir` is ever put.
         Fix: vfs_vnode_put() each when non-NULL. Put `dir` before the
         vfs_rmdir on line 150.
       - test_fat32.c:254  fat32_get_root_node() allocates a new vnode on every
         call (kernel/fs/fat32.c:2575). This one is never freed.
         Fix: slab_free(root) when non-NULL, as the block at line 554 does.
     Count: unchanged.
     Check: full run still PASS. For the fd leak, vfs_test_live_files() before
     and after the block must match once fixed.

F11  [DONE] libc/user/file.c:185-191, :206, :230   bug   [READ]
       - fwrite to stdout computes size * nmemb at line 186 before the
         overflow check at line 193. Move the check above the stdout branch.
       - ftell(stdout) ignores bytes still held in stdout's buffer, and fseek
         does not flush them first, so a position taken or set while stdout is
         a file is wrong by the buffered amount.
         Fix: call fflush(stream) at the top of fseek and ftell when stream
         is stdout.
     Add tests with F15 (file streams), which is where these become reachable.

F12  [DONE] small bugs, each a one-line change   [READ]
       a. user/apps/sh/exec.c:51  handle_sigchld calls waitpid, which sets
          errno, and can interrupt code that is about to read errno.
          Fix: save errno on entry and restore it before returning.
       b. user/apps/mkdir.c:14  make_parents starts at `path + 1`, which is
          past the terminator for an empty argument (`mkdir -p ""`).
          Fix: return at once when path[0] == '\0'.
       c. libc/user/term.c:518-537  term_key treats every failed read as
          "nothing yet". With timeout_ms < 0 and stdin closed or broken it
          spins forever.
          Fix: when read returns < 0 and errno is neither EAGAIN nor EINTR,
          return TERM_KEY_EOF.
       d. libc/user/dirent.c:23-26  opendir sets errno to ENOTDIR even when
          fstat itself failed, and after close() may have changed errno.
          Fix: set ENOTDIR only when fstat succeeded and the node is not a
          directory; otherwise keep fstat's errno across the close.
       e. libc/kernel/panic.c:159-165  kernel_panicked is tested and then set.
          Two cores panicking together both pass the test and interleave their
          reports.
          Fix: one atomic exchange; the loser parks in the wfe loop.

PART 5 - IMPROVEMENTS AND REFACTORS
================================================================================

R1   One userspace test header.
     user/apps/utest.h is reimplemented in test_libc.c:24-47, test_tools.c:37-47,
     test_restart.c:617-628 and stress.c:55-78. The fork-with-pipes runner is
     written four times: test_tools.c:50, test_sh.c:18, test_libc.c:979 and
     :1266.
     Removes: about 150 duplicated lines and four ways of reporting a failure.
     Risks: the "all N tests passed" counts shift, so every USER_SUITES minimum
     has to be re-read; test_restart prints "[FAILED]", which the harness greps
     for, so its failure text must keep working.

R2   Kernel test helpers in kernel/tests/test.h.
     waiters_all_blocked / all_done / count_done / count_blocked are duplicated
     in test_semaphore.c:128-168 and test_completion.c:154-194. The sequence
     "set SIGUSR1 pending on process 0, sched_unblock the task, wait, clear the
     bit" is written out about nine times across test_wait.c, test_tty.c,
     test_semaphore.c and test_completion.c.
     Removes: about 120 lines. Risk: low; the helpers are small and static.

R3   libc/src/string.c:271-326   memcpy and memmove load and store through
     `uint64_t *` at whatever alignment the caller passed, and the build has
     no -fno-strict-aliasing. It behaves correctly today (20,000 random cases
     matched the host). It is undefined behaviour that a compiler upgrade or
     LTO could act on.
     Fix: a word type declared
         typedef uint64_t __attribute__((may_alias, aligned(1))) word_t;
     Risk: none functionally; check the generated code is unchanged in size.

R4   A host-side comparison test for libc/src.
     printf.c, string.c, stdlib.c and ctype.c have no kernel or syscall
     dependencies, so they compile on the build host. Compiling them with every
     public name prefixed (-Dsnprintf=p_snprintf and so on, through a
     force-included header), stubbing __libc_write, and comparing against the
     host libc over generated inputs takes under a second and found F06.
     Would add: a script under scripts/ and a CI step.
     Risk: host libcs differ on undefined cases ("%5%"); the generator must
     stay inside defined behaviour.

R5   user/apps/ps.c:63   field(blob, "Pid:") finds its value only because
     /proc/<pid>/status prints "Pid:" before "PPid:"; "Pid:" is also a
     substring of "PPid:". Match at the start of a line instead.

     of Part 1, whose changes do not touch the filesystem; not repeated on the
     unmodified tree and the cause was not traced. QEMU is killed without a
     sync, which may or may not matter. Candidates: an unlink-while-open path
     (test_vfs.c:272 leaks exactly such an fd, though that file is empty), or
     a failed write in the fault-injection loop at test_fat32.c:745.

K2   Bad user pointers return EINVAL where POSIX says EFAULT:
     kernel/core/syscall.c:112-116 (copy_buf_from_user), :138-143,
     :449 (gettimeofday), :471 (clock_gettime), and exec's argv copy (errno 22
     observed). Only sigaltstack uses EFAULT. No test pins either value.

K3   kernel/core/syscall.c:1358   getdents with count 0 returns 0 before the
     fd is looked at, so a bad fd is not reported.

K4   kernel/core/syscall.c:453 and :476   gettimeofday and CLOCK_REALTIME
     return time since boot, while st_mtime is wall-clock (build date plus
     uptime). The comment marks this as planned work.

K5   kernel/mm/heap.c:18 HEAP_MAX_ALLOC is 8 MiB, but pmm.h:10 PMM_MAX_ORDER 10
     caps a contiguous block at 4 MiB, and heap_expand adds a header and footer
     then rounds up to a power of two. heap_malloc of 4 MiB therefore returns
     NULL (seen as ENOMEM from write at exactly 4 MiB), and so does anything
     above about 4 MiB minus the overhead. F07 worked around it by lowering
     SYSCALL_MAX_RW_SIZE to 1 MiB; HEAP_MAX_ALLOC still overstates what can be
     served.

CHECKED AND FOUND FINE
--------------------------------------------------------------------------------
  - test_syscall.c:831-832 (pread/pwrite with offset -1 on the terminal) looked
    weak but is not: vfs_pread rejects the offset before the file type
    (kernel/fs/vfs.c:769), and without that check the calls would block or
    succeed, which the test would notice.
  - strtol, strtoul, atoi, memcpy, memmove, memset, memcmp, strncmp, strstr,

    checks, except "oversized cluster" (255), which is refused by the
