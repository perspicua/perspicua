BRANCH STRUCTURE
----------------

  main        Stable, always flashable. Tagged with version numbers.
              Never commit directly here. Only receives merges from dev
              (or hotfix branches).

  dev         Integration/staging branch. All feature branches merge here
              first. This is where integration testing and hardware
              validation happen before anything reaches main.

  feature/*   Short-lived branches for individual features or fixes.
              Always branch off dev, not main.

  hotfix/*    Urgent fixes for bugs found in a stable main release.
              Branch off main, merge back into BOTH main and dev.


TYPICAL FEATURE WORKFLOW
------------------------

  1. Branch off dev:
       git checkout dev
       git pull origin dev
       git checkout -b feature/your-feature-name

  2. Do your work and commit locally.

  3. Push and open a PR into dev (not main):
       git push origin feature/your-feature-name

  4. Review, test on hardware if needed, then merge into dev.

  5. Delete the feature branch after merging.


PROMOTING DEV TO MAIN (Stable Release)
---------------------------------------

  1. Thoroughly test the dev branch on hardware.

  2. Open a PR from dev into main.

  3. After merging, tag the release on main:
       git tag -a v1.2.0 -m "Stable: brief description of what's in this release"
       git push origin v1.2.0


HOTFIX WORKFLOW
---------------

  1. Branch off main:
       git checkout main
       git pull origin main
       git checkout -b hotfix/describe-the-fix

  2. Apply the fix and commit.

  3. Merge into main AND dev (both need the fix):
       git checkout main
       git merge hotfix/describe-the-fix
       git tag -a v1.2.1 -m "Hotfix: describe the fix"

       git checkout dev
       git merge hotfix/describe-the-fix

  4. Push everything and delete the hotfix branch.


BRANCH PROTECTION RULES (set these up in GitHub)
-------------------------------------------------

  main:   Require PR + at least 1 review. No direct pushes.
  dev:    Require PR. Direct pushes only by maintainers if needed.


NAMING CONVENTIONS
------------------

  feature/uart-dma-fix
  feature/gpio-irq-handler
  hotfix/boot-hang-fix
  v1.0.0, v1.1.0, v1.1.1   (major.minor.patch)


VISUAL OVERVIEW
---------------

  feature/x ──┐
  feature/y ──┼──► dev ──► (hardware tested) ──► main ──► tag vX.Y.Z
  feature/z ──┘

  main ──► hotfix/* ──► main (tagged) + dev


================================================================================
  When in doubt: feature branches go into dev, dev goes into main, main is
  always something you could flash to a board right now.
================================================================================
