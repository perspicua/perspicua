Perspicua Development Ideas
===========================

This is the feature/idea BACKLOG (the "what"). For the recommended build ORDER
(the "when"), see order.txt. Items are tagged [DONE] / [PARTIAL] / [TODO].
Difficulty and Impact are rough planning estimates, not promises.

--------------------------------------------------------------------------------
1. ROBUSTNESS & CORRECTNESS  (make the base bullet-proof — highest priority)
--------------------------------------------------------------------------------
These are the load-bearing pieces. Features built on a shaky base inherit the
shakiness; harden here first.

  - Generic Wait-Queue / Condition-Variable Primitive
      Difficulty: Medium | Impact: Very High
      Details: One reusable wait_queue_t with prepare_to_wait / wake_one / wake_all
        and a condition-check loop, replacing the hand-rolled per-subsystem queues
        in tty, pipe, sd, and the sleep queue. Should be signal-interruptible.
      Benefit: Removes the class of lost-wakeup / double-enqueue bugs; prerequisite
        for clean select/poll, futexes, and blocking drivers.
  - Sleeping-Lock Family (build on the existing kmutex)
      Difficulty: Medium | Impact: High
      Details: Add rwsem (read/write), semaphore, and completion on top of the wait
        queue. Give lockdep coverage to sleeping locks too.
      Benefit: Lets read-mostly structures (mount table, process table) scale, and
        makes long/blocking critical sections correct without busy-waiting.
  - Kernel Preemption Safety (preempt_count)
      Difficulty: Medium-High | Impact: High
      Details: A per-CPU preempt_disable/enable count; the timer tick only reschedules
        when preemptible. Makes plain spinlocks safe to hold across a tick.
      Benefit: Fixes the latent priority-inversion hazard of holding non-irqsave
        spinlocks across preemption; prerequisite for a preemptive kernel.
  - Graceful Out-of-Memory Handling
      Difficulty: Medium | Impact: High
      Details: Replace PANIC-on-allocation-failure (pmm/mmu/process/elf paths) with
        error returns that unwind cleanly; add an OOM policy for user allocations.
      Benefit: A single failed 4KB allocation should never take down the whole system.
  - Unified Buffer Cache
      Difficulty: Medium-High | Impact: High
      Details: The page cache (fs/pagecache.c) and the block cache (driver/block.c)
        cache the same data twice. Collapse into one cache keyed by (device, block)
        or (inode, offset), read through it from the FS.
      Benefit: Halves cache memory, removes a second coherence problem, simplifies
        writeback.
  - VFS Inode / Dentry Cache with Refcounted Vnodes
      Difficulty: Medium-High | Impact: High
      Details: Today lookup() allocates a fresh vnode per path resolution. Cache
        vnodes by identity, refcount them, and add a name (dentry) cache.
      Benefit: Avoids repeated disk directory scans, gives stable inode identity
        (also cleans up the page-cache keying), enables hardlinks and rename safety.
  - Filesystem Crash Consistency
      Difficulty: High | Impact: High
      Details: FAT32 has no ordering/journaling — a panic mid-write can cross-link
        clusters or corrupt directories. Options: (a) an fsck-lite pass at mount,
        (b) ordered metadata writes, (c) move to a journaling FS (see ext2 + journal).
      Benefit: Survives power loss / panic without silent filesystem corruption.
  - Robust User-Memory Access
      Difficulty: Low-Med | Impact: Medium
      Details: validate_user_buffer has a TOCTOU vs. concurrent unmap; rely on the
        fault-fixup copy_to/from_user path as the source of truth and treat the
        pre-check as advisory. Add access_ok-style range checks uniformly.
      Benefit: Removes a race that matters once threads share an address space.
  - Full sigaction Semantics
      Difficulty: Medium | Impact: Medium
      Details: SA_RESTART (restart interrupted syscalls), SA_SIGINFO + siginfo_t,
        sigaltstack, real-time (queued) signals, and correct mask save/restore.
      Benefit: Real programs and language runtimes depend on these; current signal
        support is minimal.
  - Panic / Oops with Stack Unwind + dmesg Ring Buffer
      Difficulty: Low-Med | Impact: Medium
      Details: We already generate a symbol table (gen_symtab.py); use it to print a
        symbolized backtrace on panic. Add an in-memory kernel log ring exposed via
        a dmesg syscall or /proc/kmsg.
      Benefit: Turns "it hung" into an actionable stack trace; essential for debugging.
  - Hung-Task / Watchdog Detector
      Difficulty: Low | Impact: Medium
      Details: A periodic check that flags tasks blocked far too long or a core that
        stops taking timer ticks; optionally a hardware watchdog on real HW.
      Benefit: Surfaces deadlocks and livelocks instead of silent hangs.
  - RCU or Seqlocks for Read-Mostly State
      Difficulty: High | Impact: Medium
      Details: The process table and mount table are read constantly (schedule,
        signals, path resolution) but written rarely. A seqlock/RCU removes them
        from the hot lock path.
      Benefit: SMP scalability; removes lock contention the current design will hit.
  - Consistent errno / Error Mapping
      Difficulty: Low | Impact: Medium
      Details: Map internal -PERS_ERR_* codes to POSIX errno at the syscall boundary
        consistently, and set errno in every libc wrapper.
      Benefit: Ported software and users see meaningful, standard error codes.

2. KERNEL ARCHITECTURE & PERFORMANCE
--------------------------------------------------------------------------------
  - Demand Paging (On-Demand ELF Loading)
      Difficulty: High | Impact: Very High
      Details: Load 4KB pages from SD on page fault instead of eagerly in elf_load;
        needs the unified buffer cache and a per-vma backing map.
      Benefit: Faster process start, much lower RAM use, enables large binaries.
  - munmap / mprotect / mremap  (mmap currently has no way to unmap!)
      Difficulty: Medium | Impact: High
      Details: mmap reserves and maps but there is no munmap or mprotect, so mapped
        regions leak and permissions are fixed. Track VMAs and support teardown and
        permission change.
      Benefit: Correct memory lifecycle; prerequisite for a real allocator and JITs.
  - brk / sbrk (or a real anonymous-VMA heap)
      Difficulty: Low-Med | Impact: Medium
      Details: Give libc malloc a growable heap instead of leaning on fixed mmap.
      Benefit: Standard allocator behavior; less fragmentation.
  - Kernel Preemption & Priority / MLFQ Scheduling
      Difficulty: High | Impact: Medium-High
      Details: EL1 preemption (needs preempt_count) plus priorities, fair scheduling,
        and cross-core load balancing on top of the existing per-core runqueues.
      Benefit: Responsiveness under load; prevents a CPU-bound task starving others.
  - Shared Memory IPC (mmap MAP_SHARED, shm_open)
      Difficulty: Medium | Impact: High
      Details: Share physical frames between address spaces via the page cache /
        anonymous shared objects.
      Benefit: High-performance IPC; foundation for a graphics server.
  - I/O Multiplexing (select / poll / epoll)
      Difficulty: Medium | Impact: High
      Details: Per-fd readiness + wait queues (needs the generic wait-queue primitive).
      Benefit: Non-blocking servers, event loops, and porting complex tools.
  - Futexes
      Difficulty: Medium | Impact: High
      Details: Fast userspace mutex support (needs shared memory + wait queues).
      Benefit: Efficient user-space locking; required for real pthreads/mutexes.
  - Tickless / High-Resolution Timers
      Difficulty: Medium | Impact: Low-Med
      Details: Program the generic timer for the next event instead of a fixed 100Hz
        tick; a monotonic clock source and hrtimer wheel.
      Benefit: Lower idle power, accurate sleeps, real timerfd/nanosleep.

3. SYSCALL LAYER (fill the POSIX gaps)
--------------------------------------------------------------------------------
  - getppid()                      Trivial | Medium  — parent field already tracked.
  - dup()                          Trivial | Medium  — lowest free fd; one-liner on dup2.
  - dup3() / O_CLOEXEC on dup      Trivial | Low
  - pread64 / pwrite64             Low     | Medium  — positional I/O; reuse lseek+rw.
  - gettimeofday / clock_gettime   Low     | High    — realtime + monotonic clocks;
                                                        needs a boot wall-clock offset
                                                        (ideally an RTC driver).
  - nanosleep                      Low     | Medium  — sub-ms sleep vs. current SYS_SLEEP.
  - truncate / ftruncate           Low-Med | Medium  — FAT32 can shrink chains; expose it.
  - fstat (by fd) / lstat          Low     | Medium  — STAT is path-only today.
  - munmap / mprotect              Medium  | High    — see section 2.
  - access / faccessat             Trivial | Low
  - umask / chmod / chown (stubs)  Low     | Low     — FAT has no perms; stub for ports.
  - getrusage / times              Low     | Low     — schedstat already tracks a lot.
  - poll / select / ppoll          Medium  | High    — see section 2.
  - SIGSTOP / SIGCONT + job control Low    | Medium  — set STOPPED state, wake on CONT.
  - reboot / poweroff              Trivial | Low     — clean shutdown + sync.
  Note: consider aligning syscall numbers with Linux/AArch64 to ease porting.


--------------------------------------------------------------------------------
4. FILESYSTEM & STORAGE
--------------------------------------------------------------------------------
  - A Second Filesystem (ext2 or a simple journaling FS)
      Difficulty: High | Impact: High
      Details: Implementing a real inode-based FS both exercises/validates the VFS
        abstraction and gives crash consistency FAT32 can't.
      Benefit: Proves the VFS is truly generic; a journal gives durability.
  - tmpfs / working ramfs write path
      Difficulty: Low-Med | Impact: Medium
      Details: A memory-backed FS for /tmp; make ramfs actually writable.
      Benefit: Fast scratch space; needed by many build/porting workflows.
  - FAT32 Long-File-Name (LFN) *creation*
      Difficulty: Medium | Impact: Medium
      Details: Reads LFN today but create/mkdir write truncated 8.3 names; generate
        LFN directory entries + checksums on write.
      Benefit: Real filenames survive a round-trip through the shell.
  - Partition Tables (MBR is parsed; add GPT) + multiple partitions/mounts
      Difficulty: Low-Med | Impact: Low-Med
  - /proc/mounts, /proc/cpuinfo, /proc/stat, /proc/self
      Difficulty: Low | Impact: Medium — many tools parse these.
  - Symlinks / hardlinks (needs inode FS), atime/mtime, statfs
      Difficulty: Medium | Impact: Medium
  - Additional block backends: ramdisk (easy, great for tests), later USB mass
      storage / NVMe.

5. DRIVERS & DEVICES
--------------------------------------------------------------------------------
  - Core /dev nodes: /dev/null, /dev/zero, /dev/full, /dev/tty, /dev/random +
      /dev/urandom (needs an entropy source).      Low | High
  - RTC / hardware clock driver (wall-clock time across boots).  Low-Med | Medium
  - Watchdog driver (real HW).                                    Low     | Medium
  - Device model maturity: support multiple instances of a driver (probe currently
      binds only the first matching FDT node), a persistent struct device with a
      lifetime, and orderly teardown.                             Medium  | Medium
  - Framebuffer: double-buffering / vsync; a /dev/fb ioctl set.   Medium  | Medium
  - Input: USB HID keyboard/mouse (big) or a simpler console path. High   | Medium
  - PCIe + USB host stacks (large, unlock networking + storage).  Very High | High

6. USER-SPACE, LIBC & SHELL
--------------------------------------------------------------------------------
  LIBC (missing pieces confirmed absent):
  - ctype.h (isdigit/isalpha/isspace/toupper/...)   Trivial | High — pure tables.
  - strerror()                                       Trivial | High — errno -> string.
  - strdup() / strndup()                             Trivial | High — malloc+copy.
  - setjmp() / longjmp()                             Low     | Medium — AArch64 asm.
  - time.h (time, gmtime, localtime, strftime)       Low-Med | Medium — needs clock syscalls.
  - Proper buffered stdio (FILE*), fgets/fputs/scanf family, snprintf bounds.
  - qsort / bsearch; printf float support; a minimal libm.
  - Consistent errno in every wrapper (see section 1).

  CORE POSIX UTILITIES ("base system"):
  - Currently missing as binaries: mkdir, rm, cp, mv, ps, kill, grep, wc, touch,
      head/tail, env, sleep, clear, mount.
      Difficulty: Low-Med | Impact: High — transitions from experiment to usable system.
      (Note: the mkdir/rm *syscalls* exist; the *binaries* don't — the shell can
       only create files via > redirection today.)

  SHELL (sh.c):
  - $? exit-status variable + $VAR expansion         Trivial-Low | Medium.
  - Correct pipeline exit-code propagation           Low | Medium.
  - Globbing (*, ?, [..])                            Low-Med | Medium.
  - Job control (fg/bg/jobs) — needs SIGSTOP/CONT     Medium | Medium.
  - Scripting: if/for/while, &&/||, ; , subshells, here-docs.  Medium | Medium.
  - Line editing: history, tab completion.            Medium | Medium.


--------------------------------------------------------------------------------
7. THREADS & CONCURRENCY
--------------------------------------------------------------------------------
  - Threading (clone() + TLS)
      Difficulty: High | Impact: High
      Details: Multiple tasks sharing one address space + fd table; per-thread
        signal mask, TID, TLS via tpidr_el0. Depends on solid MM (section 1/2),
        futexes, and per-task (not per-process) signal state.
      Benefit: Multi-threaded apps use all cores; unlocks pthreads.
  - pthreads library on top of clone + futex.        Medium | High.
  - Note: several current structures assume one task per process (e.g. schedule()
    reads the owning process's ASID lock-free; signal delivery targets main_task).
    These must be revisited when threads land.


--------------------------------------------------------------------------------
8. SECURITY & HARDENING
--------------------------------------------------------------------------------
  - W^X enforcement everywhere (kernel already sets PXN/UXN; audit user mappings).
  - ASLR (user stack/mmap/PIE base) + user stack canaries.   Medium | Medium.
  - PAN / privileged-access-never (SMAP-equivalent) so the kernel can't accidentally
      deref user pointers outside the uaccess helpers.          Low-Med | Medium.
  - KASLR for the kernel image.                                  Medium | Low-Med.
  - A privilege/permission model (uid/gid, capabilities) — large, needed for
      multi-user.                                                High | Medium.
  - seccomp-style syscall filtering (long-term).


--------------------------------------------------------------------------------
9. OBSERVABILITY & TESTING
--------------------------------------------------------------------------------
  - `just test` target: boot QEMU, run the kernel self-tests, capture serial, exit
      pass/fail (enables CI).                                     Low | High.
  - Missing test suites: test_vfs, test_fat32, test_signals, test_pipe, test_uaccess,
      test_mutex; a userspace syscall test harness.               Low-Med | Medium.
  - Syscall-layer fuzzing (feed random/boundary args; catch OOB like the mmap-fd bug
      before users do).                                           Medium | Medium.
  - dmesg ring buffer + kernel log levels; /proc/kmsg.           Low | Medium.
  - ftrace-lite: function/latency tracing; per-subsystem counters (schedstat exists).
  - Split tests out of the shipped image (they compile into every build today).


--------------------------------------------------------------------------------
10. LONG-TERM STRATEGIC
--------------------------------------------------------------------------------
  - Network Stack (LWIP integration or a minimal UDP/IP)
      Difficulty: High | Impact: Very High — remote access, servers; needs a NIC
      driver (USB/PCIe) and I/O multiplexing.
  - Graphics Server (Wayland-lite compositor) — needs shared-memory IPC + input.
  - Dynamic Linking (ld.so + shared objects) — mostly a user-space loader challenge.
  - POSIX ABI compatibility: align syscall numbers/structs with Linux/AArch64.
  - Namespaces / containers, cgroup-style resource limits.
  - Virtualization via EL2 (run guest OSes) — the final frontier.
  - Power management: CPU idle states, DVFS, suspend.
