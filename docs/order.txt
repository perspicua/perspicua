Perspicua Build Order
=====================

This file is the ORDER in which to build things so every layer rests on a solid
one below it. The full catalog of ideas lives in ideas.txt; this file is about
sequencing, dependencies, and what "done" means for each step.

Guiding rule: correctness of the foundation before breadth of features. A bug in
the scheduler, the MMU, or the buffer cache costs 10x more once demand paging,
threads, and a network stack sit on top of it.

================================================================================
KERNEL AUDIT 
================================================================================

Scope: mm/{pmm,mmu,slab,heap,asid}, sched/{sched,process}, arch/{boot,vector,
switch,uaccess,exception}, core/{syscall,signals,lock,mutex}, fs/{vfs,fat32,pipe}.
Ordered by exploitability and blast radius. Line numbers are from the audited
tree (branch `dev`, at 3ea7927).

### [BUG-018] `heap_free` dereferences an unvalidated header
- **Location**: `kernel/mm/heap.c:212-220`
- **Severity**: Medium
- **Description**: For any pointer `slab_owns()` rejects, `heap_free` assumes a
  32-byte header sits immediately before it and reads `block->size` to locate the
  footer. There is no magic field in `struct heap_block_header` to confirm that.
  A stray pointer — a PMM page, a stack address, an offset into a valid block —
  produces a wild read at `block + 32 + garbage`, and if that happens to contain
  the redzone value, the block is spliced into the free list and the allocator is
  compromised. The redzone check is doing double duty as a validity check it
  cannot perform.
- **Suggested Fix**: Add `unsigned int magic` to the header, set it on allocation,
  clear it on free, and validate it before touching `size`. Also range-check that
  `block` lies inside a region the heap actually owns (keep a small list of
  `heap_expand` regions) — cheap, and it turns silent corruption into a clean
  panic with the offending pointer.

### [BUG-019] Unbounded `getdents` size and O(n) validation with interrupts masked
- **Location**: `kernel/core/syscall.c:281-307` (`SYS_GETDENTS`), `:37-88`
  (`validate_user_buffer`)
- **Severity**: Medium
- **Description**: Two related problems. First, `SYS_GETDENTS` is the only
  buffer-taking syscall with no `SYSCALL_MAX_RW_SIZE` cap, so `count` flows
  unchecked into `heap_malloc` (up to the 8 MB `HEAP_MAX_ALLOC`) — and `SYS_READ`/
  `SYS_WRITE` already allow 4 MB per in-flight call, per process, which is ample
  to exhaust the kernel heap and reach BUG-009. Second, `validate_user_buffer`
  walks the range one 4 KB page at a time, and for each page acquires
  `process_table_lock` once and `mmu_lock` once (inside `mmu_user_query`) — with
  interrupts disabled for the whole loop. A 4 MB buffer is 1024 iterations of
  lock/unlock with IRQs masked on that core; an 8 MB `getdents` is 2048. Timer
  ticks are lost, and every other core contends on `mmu_lock`.
- **Suggested Fix**: Cap `count` in `SYS_GETDENTS` like the other paths. Restructure
  `validate_user_buffer` to take `process_table_lock` once, hoist the `mmu_lock`
  acquisition out of the per-page loop (add an `mmu_user_query_locked` variant),
  and walk L3 tables a page-table-page at a time instead of re-descending from the
  PGD for every page. Better still, drop the pre-validation entirely and rely on
  the `ldtr`/`sttr` + fixup path, which is what actually enforces safety (see
  BUG-022 and IMP-006).

### [BUG-020] Non-IRQ-safe spinlocks held across preemption points
- **Location**: `kernel/sched/process.c:464-470` and `:798-806` (`p->fd_lock`),
  `kernel/fs/pipe.c:122-152` (`pipe->lock` held across `pipe_wait` → `schedule()`)
- **Severity**: Medium
- **Description**: `spin_lock` neither disables interrupts nor increments a
  preemption counter. Several call sites hold it across code that can be preempted
  or that deliberately calls `schedule()`. `pipe_read` acquires `pipe->lock` and
  keeps it while calling `pipe_wait`, which does release it around the switch — but
  the lock is *re-acquired* immediately after `schedule()` returns and only then
  are IRQs restored, so the ordering is subtle and one refactor away from a
  deadlock. `process_exec` and `process_fork` hold `fd_lock` across an ordinary
  preemptible region: if the timer fires there and the next task on that core
  spins on the same `fd_lock` with IRQs already masked by an outer `irqsave`, the
  holder can never be rescheduled on that core.
- **Suggested Fix**: Make the rule explicit and enforce it: any lock that can be
  taken from IRQ context or held while another core may spin on it uses
  `spin_lock_irqsave`. Add a `preempt_count` to `struct task`, incremented by
  `spin_lock` and asserted to be zero at the top of `schedule()` (except for the
  documented voluntary-block paths) — lockdep is already in the tree and is the
  natural home for that check.

### [BUG-021] `switch_context` does not save PSTATE/DAIF; syscalls run with IRQs masked
- **Location**: `kernel/arch/switch.S:6-31`, `kernel/arch/vector.S:166-170`
- **Severity**: Medium (architectural)
- **Description**: Two coupled issues. Taking an SVC from EL0 sets `PSTATE.I`, and
  nothing in `sync_handler` re-enables it — so **every syscall executes to
  completion with interrupts masked** on that core. A process doing a 4 MB `read`
  from the SD card blocks the timer tick, defeats preemption entirely, and makes
  the round-robin scheduler cooperative-only for the duration. Meanwhile
  `switch_context` saves only the callee-saved GPRs, `fp`, `lr` and `sp` — DAIF is
  not part of `struct cpu_context`, so the interrupt-enable state effectively
  leaks between tasks across a switch. The `irq_save`/`irq_restore` pairs around
  `schedule()` paper over this, but the invariant is undocumented and every new
  blocking path has to rediscover it.
- **Suggested Fix**: Re-enable IRQs early in the syscall path (`msr daifclr, #2`
  after `save_all` in `sync_handler`, before `bl exception_sync_handler`), which
  requires auditing syscall handlers for re-entrancy first — this pairs naturally
  with the `preempt_count` work in BUG-020. Independently, either add DAIF to
  `struct cpu_context` or write a comment at the top of `switch.S` stating that
  callers must own the interrupt state, and assert it in `schedule()`.

### [BUG-022] Copy-on-write fault handling is not atomic
- **Location**: `kernel/mm/mmu.c:648-674` (`mmu_handle_cow`)
- **Severity**: Medium
- **Description**: The function queries the PTE (taking and releasing `mmu_lock`),
  allocates a page, `memcpy`s 4 KB, and only then calls `mmu_user_map_page` (taking
  `mmu_lock` again). Nothing holds the mapping stable across that window. Two
  cores faulting on the same COW page in the same address space each allocate a
  copy and each install one, and `mmu_user_map_page` drops a reference on the old
  physical page as it overwrites the PTE — so the shared page's refcount is
  decremented twice for a single reference. It also always copies, even when the
  refcount has already fallen to 1 and the page could simply be made writable —
  the common case after a child exits, and a measurable `fork`-heavy regression.
  This is the same TOCTOU shape as `validate_user_buffer` → `copy_to_user`: the
  check and the use are separated, and only the fault-fixup path makes the latter
  safe.
- **Suggested Fix**: Perform the whole transition under `mmu_lock`: re-read the PTE
  after acquiring the lock, bail out if `MMU_PTE_COW` has already been cleared
  (another core won the race — just return success and let the instruction
  retry), and add the refcount==1 fast path that flips `AP_RO`/`COW` in place with
  a single `tlbi` and no copy at all.

### [BUG-023] `mmu_destroy_user_pgd` walks and frees page tables without `mmu_lock`
- **Location**: `kernel/mm/mmu.c:347-390`
- **Severity**: Medium
- **Description**: Every other page-table walker in the file (`mmu_user_map_page`,
  `mmu_user_unmap_page`, `mmu_user_query`, `mmu_copy_user_pgd`) serialises on
  `mmu_lock`; the destroy path does not, while doing the most destructive thing in
  the file. It races with `validate_user_buffer` (which walks the same PGD from
  `mmu_user_query`) and with a COW fault taken on another core, both of which are
  reachable for a process being torn down. It is also called from
  `mmu_copy_user_pgd`'s `oom:` label — after that function has already released
  the lock, which is correct today only by accident of the label's placement.
- **Suggested Fix**: Acquire `mmu_lock` for the walk. Because `pmm_free_page` is
  called from inside it and takes `pmm_lock`, keep the existing
  `mmu_lock → pmm_lock` order (which `mmu_user_map_page` already establishes) and
  document that ordering in a comment at the top of `mmu.c` alongside the
  `process_table_lock → fd_lock` note in `process.c`.

### [BUG-024] `mmap` gaps: silent unbacked mappings, unlocked fd access, `addr` ignored
- **Location**: `kernel/core/syscall.c:738-811` (`SYS_MMAP`)
- **Severity**: Medium
- **Description**: Three defects in one handler. (a) For a file-backed mapping
  where the vnode has no `->mmap` operation, the code falls through and returns
  `new_region` with **no pages mapped at all** — the caller gets a valid-looking
  pointer that faults on first touch and kills the process, instead of
  `-ENODEV`. (b) `p->fd_table[fd]` is read without `p->fd_lock`, racing a
  concurrent `close`/`dup2` on another core into a freed `struct vfs_file`.
  (c) `tf->x[0]` (the `addr` hint) is read but never used, so `MAP_FIXED` is
  silently ignored — a mapping request at a specific address quietly lands
  somewhere else, which is the kind of failure that only shows up much later.
- **Suggested Fix**: Return `-PERS_ERR_NOT_IMPLEMENTED` when a file-backed request
  has no `->mmap`; take `fd_lock` and a reference on the file for the duration;
  and either honour `MAP_FIXED` or reject it explicitly. The `mmap_fail` cleanup
  loop is otherwise good — it is one of the better error paths in the file.

### [BUG-025] User virtual address space is allocated monotonically and never reused
- **Location**: `kernel/sched/process.c:196-229` (`process_va_alloc`,
  `process_va_free`)
- **Severity**: Medium
- **Description**: `va->next_va` only ever increases. `process_va_free` removes the
  bookkeeping record but returns nothing to the allocator, so a process that maps
  and unmaps repeatedly marches `next_va` toward the `0x8000000000` ceiling and
  then fails all further mappings, while `USER_VA_MAX_REGIONS` (64) caps the number
  of live regions at any instant. Combined with the absence of `munmap` — there is
  no syscall to release a mapping at all — a long-running process cannot recycle
  address space. This is the structural blocker for the `mmap`/shm work in Phase 4.
- **Suggested Fix**: Replace the fixed array with a proper sorted VMA list (base,
  length, prot, flags, backing file+offset), with first-fit or best-fit placement
  and merging of adjacent free ranges. That single change unlocks `munmap`,
  `mprotect`, `MAP_FIXED`, demand paging, and lazy stack growth — see IMP-002.

### [BUG-026] `kmutex_unlock` does not verify ownership
- **Location**: `kernel/core/mutex.c:90-114`
- **Severity**: Low
- **Description**: The function never compares `m->owner` against
  `sched_get_current()`. Any task calling it on a mutex held by another task
  clears `owner`, resets `depth` to 0 and wakes a waiter — silently transferring
  the lock and leaving the real owner running unprotected inside its critical
  section. Similarly, unlocking an already-unlocked mutex is accepted. Nothing in
  the tree does this today, but it is exactly the class of bug that becomes
  unfindable once SD I/O and the page cache both take the lock.
- **Suggested Fix**: Panic (or `pr_err` + return) when
  `m->owner != sched_get_current()` or `m->depth == 0`. Cheap, and it converts a
  silent corruption into an immediate, attributable failure.

### [BUG-027] Miscellaneous correctness and robustness nits
- **Severity**: Low
- `kernel/mm/slab.c:97,106` — `slab_total_pages++/--` is a non-atomic
  read-modify-write on a global; `slab_release_page` is called *outside* the class
  lock, so the counter drifts on SMP. Make it `atomic_t` or move the decrement
  inside the lock.
- `kernel/mm/slab.c:150` — `struct slab_obj *obj = sp->free_list;` is dereferenced
  with no NULL check. The list invariants make it unreachable today; a defensive
  `PANIC("slab: partial page with empty free list")` documents the invariant and
  catches its violation at the source rather than three frames later.
- `kernel/mm/pmm.c:229` — `mem_size_cells = fdt32_to_cpu(reg[2])` reads a single
  32-bit cell as the memory size without consulting `#address-cells`/`#size-cells`.
  For the standard 2/2 layout `reg[2]` is the *high* half of the size, so this
  works only by coincidence of the current DTB and caps usable RAM at 4 GB. Parse
  the cell counts from the parent node.
- `kernel/include/arch/exception.h:23` — `struct exception_trap_frame` must be
  exactly 800 bytes to match `save_all`/`restore_all` in `vector.S`, and every
  field offset must match the hardcoded immediates there. There is no
  `_Static_assert` — unlike `struct cpu_context`, which has one in `sched.c:26`.
  Add `_Static_assert(sizeof(struct exception_trap_frame) == 800, ...)` plus
  `offsetof` assertions for `elr_el1`, `spsr_el1`, `x`, `q`.
- `kernel/arch/switch.S:41` — `task_wrapper_asm` hardcodes `mov x1, #3` for
  `SCHED_TASK_DEAD`. The *offset* of `state` is protected by a static assert; its
  *value* is not. Add `_Static_assert(SCHED_TASK_DEAD == 3, ...)`.
- `kernel/arch/uaccess.S:69` — the `__ex_table` entry pairs `.Lloop_to` (which is
  `ldrb w3, [x1], #1`, a *kernel* load) with `.Lfault_to`. A genuine kernel bug
  that faults there is silently swallowed and reported as a failed user copy.
  Remove that entry; only `.Lstore_to` needs a fixup.
- `kernel/core/syscall.c:187-196` — `SYS_YIELD` and `SYS_SLEEP` never write
  `tf->x[0]`, so they return whatever the caller passed in `x0`. Set it to
  `PERS_SUCCESS`.
- `kernel/arch/exception.c:52-62` — `exception_fixup` is a linear scan of the
  whole `__ex_table` on every abort, including the COW fault path, which is hot.
  Sort the table at build time and binary-search it.
- `kernel/sched/process.c:589` — `unsigned long riciu_secret_var;` is leftover
  debug naming for what is just `paddr_null` (compare line 561, which does the
  identical thing with a sensible name). Rename.

## 2. ARCHITECTURAL IMPROVEMENTS & FUTURE FEATURES

### [IMP-001] Demand paging and lazy stack growth
- **Target Subsystem**: Memory
- **Category**: Feature / Performance
- **Description**: Every mapping is populated eagerly. `process_create_from_file`
  allocates and maps 32 pages of stack up front, `SYS_MMAP` allocates every page
  of an anonymous region before returning, and `elf_load` faults in the whole
  image. A 256 MB `mmap` (the current cap) allocates 65 536 physical pages
  synchronously inside a syscall — with interrupts masked (BUG-021). Real
  demand paging would make `fork`+`exec` dramatically cheaper and is the
  prerequisite for a usable `mmap`.
- **Implementation Strategy**: Build on the VMA list from IMP-002. Map anonymous
  regions with no PTE at all; extend `handle_abort` so that a translation fault at
  an address inside a VMA allocates and maps on demand rather than killing the
  process. Add a guard-gap VMA below the stack and grow the stack downward on
  fault. Share a single zeroed page read-only for untouched anonymous memory and
  let the existing COW path handle the first write. Reuse `mmu_handle_cow`'s
  structure — after BUG-022 it will already do the locked re-check correctly.

### [IMP-002] Replace the linear VA allocator with a real VMA layer
- **Target Subsystem**: Memory
- **Category**: Feature / Code Quality
- **Description**: `struct va_allocator` is a 64-entry array with a monotonic
  bump pointer (BUG-025). It cannot express protection flags, file backing, or
  gaps, which is why `munmap`, `mprotect`, `MAP_FIXED`, `MAP_SHARED`, and shared
  memory are all absent. It is the single highest-leverage refactor in the memory
  subsystem — most of Phase 4 in this document is blocked behind it.
- **Implementation Strategy**: Define `struct vm_area { uintptr_t start, end; int
  prot, flags; struct vfs_file *file; vfs_off_t offset; struct vm_area *next; }`,
  keep them in an address-sorted list per process (a red-black tree later, if
  profiling justifies it), and write `vma_find(mm, addr)`, `vma_insert`,
  `vma_split`, `vma_merge`. Port `process_va_alloc` callers over, then implement
  `munmap`/`mprotect` on top. `fork` copies the VMA list; `exec` tears it down.
  This also gives `/proc/<pid>/maps` for free, which makes every later memory bug
  an order of magnitude easier to diagnose.

### [IMP-003] Preemptible kernel: `preempt_count` plus interrupts on during syscalls
- **Target Subsystem**: Scheduler
- **Category**: Performance / Hardening
- **Description**: Syscalls today are non-preemptible (BUG-021), so scheduling
  latency is bounded by the slowest syscall — currently a multi-megabyte SD read.
  There is also no mechanism preventing a preemption while a spinlock is held
  (BUG-020), which is the underlying reason several locks have to be `irqsave`
  defensively.
- **Implementation Strategy**: Add `int preempt_count` to `struct task`;
  `spin_lock`/`spin_unlock` increment and decrement it. Unmask IRQs after
  `save_all` in the SVC path. In the timer IRQ, set a `need_resched` flag rather
  than calling `schedule()` directly, and consult it in `ret_to_user` and on the
  final `preempt_count` decrement. Assert `preempt_count == 0` on entry to
  `schedule()` from the voluntary paths. Wire the assertions into the existing
  lockdep infrastructure so the test suite catches regressions.

### [IMP-004] Reference-counted task and process objects
- **Target Subsystem**: Scheduler
- **Category**: Hardening
- **Description**: Three of the six critical findings above (BUG-004, BUG-005,
  BUG-006) are the same bug: an object is freed while another subsystem still holds
  a pointer to it. `struct task` is reachable from run queues, the sleep queue,
  mutex and pipe and tty wait queues, `sched_prev_task`, `sched_cleanup`, and
  `process_table[].main_task` — and is freed based on a single core's view of its
  state. Patching each site individually will not hold as more wait queues appear.
- **Implementation Strategy**: Give `struct task` an `atomic_t refcount`;
  `get_task`/`put_task` around every stored pointer, with the final `put` doing
  the stack free and `heap_free`. Establish the rule that a task must be unlinked
  from every list before its last reference drops, and add a debug-build
  `task_on_any_list()` assertion in the destructor. Do the same for
  `struct process` so `waitpid`'s `memset` of a live PCB becomes impossible.

### [IMP-005] Faster and safer `copy_to_user`/`copy_from_user`
- **Target Subsystem**: Memory / libc boundary
- **Category**: Performance / Hardening
- **Description**: `uaccess.S` copies **one byte at a time** with `ldtrb`/`sttrb`.
  A 4 MB `read()` is 4 million iterations of a 4-instruction loop, and every
  syscall pays for it twice (into the bounce buffer, then out). Separately, the
  `validate_user_buffer`-then-copy pattern is a textbook TOCTOU that is safe today
  only because the fixup path catches the fault — meaning the expensive
  pre-validation is largely redundant (BUG-019).
- **Implementation Strategy**: Rewrite the copy routines to align the destination,
  then move 16 bytes per iteration with `ldtr x`/`sttr x` pairs, with a byte-wise
  head and tail — each with its own `__ex_table` entry that reports the correct
  residual count. Then delete most `validate_user_buffer` calls, keeping only a
  cheap `addr + len <= KERNEL_VMA && !overflow` range check, and let faults do the
  rest. Enable **PAN** (`SCTLR_EL1.SPAN` / `PSTATE.PAN`) so any kernel access to
  user memory *outside* these routines traps immediately — that is the mechanism
  that makes the check-free design safe, and it costs one boot-time register write.
  Finally, mask user pointers against the address-space bound before use to blunt
  speculative out-of-bounds reads.

### [IMP-006] Scheduler: priorities, real load balancing, tickless idle
- **Target Subsystem**: Scheduler
- **Category**: Performance / Feature
- **Description**: The scheduler is strict round-robin with no priorities, and
  work-stealing scans every other core's queue on every miss
  (`sched.c:574-581`) while holding that core's `rq_lock` — pure contention as
  core count grows. There is no accounting of how long a task has run, so
  `ptop`-style tooling has nothing real to display, and an idle core still takes
  the full timer tick rate.
- **Implementation Strategy**: Add a nice level and per-task `vruntime`; pick the
  minimum-`vruntime` runnable task (a small per-core binary heap is enough at this
  scale). Track per-core queue lengths in a lock-free array so stealing consults
  the counters before taking any lock, and only steal from the busiest core. Add
  per-task accumulated runtime, which feeds `/proc` and `ptop`. Suppress the timer
  on a core whose run queue is empty until an IPI or the next sleep deadline —
  the sleep queue is already sorted by `wake_time`, so the next deadline is O(1).

### [IMP-007] `poll`/`select` and a unified wait-queue abstraction
- **Target Subsystem**: VFS / Drivers
- **Category**: Feature
- **Description**: Pipes, the TTY, and the SD driver each hand-roll a wait queue
  out of `task->wait_next`, with subtly different unlink and wake semantics — and
  two of the critical findings above (BUG-004, BUG-005) live precisely in that
  hand-rolled code. There is no way for a process to wait on more than one
  descriptor, which blocks any non-trivial shell or server.
- **Implementation Strategy**: Introduce `struct wait_queue` with
  `wq_wait(wq, condition)`, `wq_wake_one`, `wq_wake_all`, correct
  prepare-to-wait/finish-wait ordering, and interruptible-by-signal support.
  Convert pipe, tty, and sd to it. Add a `->poll(file, wq)` vnode op returning a
  readiness mask, then implement `poll()` on top; `select()` becomes a libc
  wrapper. This is the dependency that Phase 3 "poll" and the network stack both
  sit behind.

### [IMP-008] Signal delivery completeness
- **Target Subsystem**: Scheduler / Core
- **Category**: Feature / Correctness
- **Description**: `signal_handle_pending` delivers at most one signal per return
  to userspace and re-enters only on the next trap; there is no `SA_RESTART`, so an
  interrupted syscall always returns `-PERS_ERR_INTERRUPTED` and every libc caller
  must retry by hand; there is no `sigaltstack`, so a `SIGSEGV` caused by stack
  exhaustion cannot be handled; and signals target `main_task` only, which will
  not survive the introduction of threads.
- **Implementation Strategy**: Loop over deliverable signals in
  `signal_handle_pending` until none remain or a handler frame is pushed. Record
  the syscall number and original arguments in the trap frame so a restartable
  syscall can rewind `elr_el1` by 4 and re-execute when `SA_RESTART` is set. Add
  `sigaltstack` and use it for the fault signals. When threads arrive, move
  `pending_signals` to per-task and keep `blocked_signals` per-task with the
  handler table shared per-process, matching POSIX.

### [IMP-009] Block layer and page cache hardening
- **Target Subsystem**: Drivers / VFS
- **Category**: Hardening / Performance
- **Description**: `fat32.c` reads directly through `current_fs.dev->read_blocks`
  with a single global `current_fs`, meaning exactly one FAT32 volume can ever be
  mounted, and every directory scan re-reads sectors that the page cache already
  holds. Nothing validates cluster numbers or sector addresses derived from disk
  content before they become block reads (BUG-016).
- **Implementation Strategy**: Move FAT-table and directory reads through the
  existing buffer cache rather than issuing raw `read_blocks`, and cache the FAT
  chain per open vnode so sequential reads stop re-walking it. Make `current_fs`
  an allocated per-mount structure hanging off the superblock so multiple volumes
  work. Add a validation layer at the block-device boundary that range-checks every
  LBA against the device size and returns `-EIO` rather than trusting the caller.

### [IMP-010] Per-CPU exception stacks
- **Target Subsystem**: Memory / Arch
- **Category**: Hardening
- **Description**: All exceptions are taken on the current kernel stack.
  `save_all` immediately subtracts 800 bytes; if the fault *was* a stack overflow,
  that push lands on the unmapped guard page and takes another abort, recursing
  until the CPU gives up. The stack canary in `struct task` catches overflow only
  at the next `schedule()`, which is too late to produce a usable report — and the
  guard page, which should turn overflow into a clean diagnosable fault, currently
  turns it into an unrecoverable loop.
- **Implementation Strategy**: Allocate a small per-core exception stack and switch
  `SP_EL1` to it on entry for aborts (keep the syscall path on the task stack so
  syscall handlers can still block). Detect "fault address is within one page below
  a known task stack base" and report it as a stack overflow with the faulting
  task's identity, rather than a generic abort. This is a small change that makes
  every future memory bug substantially cheaper to diagnose.

### [IMP-011] Close the test-coverage gaps the audit exposed
- **Target Subsystem**: Tests
- **Category**: Code Quality
- **Description**: The suite has good per-module coverage (`test_pmm`, `test_slab`,
  `test_heap`, `test_uaccess`, `test_mmu_user`, …) but every finding above sits in
  a gap it does not reach: adversarial syscall arguments, concurrent operations on
  shared objects, and malformed on-disk data. BUG-002, BUG-008 and BUG-010 are all
  single-argument syscall cases; BUG-001 and BUG-016 are single crafted-image
  cases; BUG-003 is a single allocation size.
- **Implementation Strategy**: Add three test families. (1) A syscall boundary
  fuzzer: for each syscall number, drive edge-case arguments — 0, 1, `SIZE_MAX`,
  negative, `KERNEL_VMA`, unmapped, and read-only user pointers — and assert the
  kernel returns an error rather than faulting. (2) Allocator property tests: for
  `heap_malloc(n)` across `n` spanning the slab/first-fit boundary and every
  block-splitting edge, assert the returned region is writable for exactly `n`
  bytes and that the redzone survives — that alone catches BUG-003. (3) A corrupt
  FAT32 image fixture with an out-of-range LFN sequence, `sectors_per_cluster == 0`
  and a cyclic cluster chain, asserting the mount is rejected cleanly. Add a
  fault-injection mode to `heap_malloc`/`pmm_alloc_page` (fail the Nth allocation)
  to exercise the OOM paths, which is where BUG-009 and several leaks live.

PHASE 1: FOUNDATION HARDENING  (finish filling the holes)
Goal: Complete the half-built features so the base is dependable. Nothing here is
architecturally hard — it is the accumulated "we'll do it later" list, and it is
what makes the system usable enough to develop against.
================================================================================

   1. Remaining POSIX syscalls
      Effort: S each | Unlocks: closes the most common porting gaps
      Scope: getppid, pread/pwrite, gettimeofday + clock_gettime (realtime +
        monotonic), nanosleep, fstat (STAT is path-only today), truncate/ftruncate.
      Done: a userspace test calls each and checks the result.
      Note: parent_pid is already tracked; SYS_DUP already exists; FAT32 can
        already shrink cluster chains, so ftruncate is mostly plumbing.
        VFS_O_TRUNC is defined in fs/vfs.h but acted on NOWHERE in the kernel,
        so open(..., O_TRUNC) on an existing file silently keeps the old
        contents — found by test_fat32, which documents the gap in place of an
        assertion. Fix it alongside truncate/ftruncate.
        CLOCK_REALTIME will be boot-relative until the RTC lands (Phase 3 item 3)
        — implement the interface now, wire the wall clock in later.

   3. procfs completeness: /proc/mounts, /proc/cpuinfo, /proc/stat, /proc/self
      Effort: S | Unlocks: monitoring tools and scripts that parse /proc
      Scope: iterate the mount table / cpu info / global counters as text.
      Done: cat of each returns well-formed output.
      Note: use the bounded procfs_append() helper — the raw
        `pos += snprintf(buf+pos, SIZE-pos, ...)` idiom overflows (that was a real
        heap-smash bug in /proc/<pid>/maps).

   4. Shell scripting basics: $? , $VAR expansion, correct pipeline exit codes
      Effort: S-M | Unlocks: any non-trivial shell usage or scripting
      Scope: track the last exit status; expand $NAME from environ; propagate the
        rightmost non-zero exit through a pipeline.
      Done: `false; echo $?` prints 1; `echo $PATH` expands.
      Note: sh.c already has expand_operators() for redirection — extend that pass.

   5. Core POSIX utility BINARIES: ps, kill, mkdir, rm, cp, mv, touch, wc, grep, env
      Effort: M | Unlocks: turns the project from experiment into usable system
      Scope: small programs over existing syscalls.
      Done: you can create/inspect/delete files from the shell without redirection.
      Note: the mkdir/rm *syscalls* already exist — only the programs are missing.
        Today `> file` redirection is the ONLY way to create a file.

PHASE 2: ROBUSTNESS PRIMITIVES  (the load-bearing infrastructure)
Goal: Build the reusable mechanisms that every advanced feature depends on, so we
build them ONCE and correctly rather than re-inventing ad-hoc versions.

Rationale: Phases 3+ (poll, demand paging, threads) all assume these exist. Doing
them now avoids retrofitting correctness into ten call sites later. This is the
single highest-leverage phase in the file.
================================================================================

   1. Generic wait-queue / condition-variable primitive
      Effort: M | Unlocks: select/poll, futexes, every future blocking driver
      Scope: one wait_queue_t with prepare_to_wait / wake_one / wake_all and a
        condition re-check loop; signal-interruptible (returns -EINTR).
      Done: tty, pipe, sd, AND kmutex are all converted to it and their bespoke
        queues are deleted; a test covers wake, signal-interrupt, and spurious
        wakeup.
      Note: struct task already has a dedicated wait_next link (separate from
        rq_next/sleep_next) — that is the hook. The bespoke queues in tty/pipe/sd
        each re-derive remove-on-wake logic slightly differently; that duplication
        is exactly what caused the earlier lost-wakeup/corruption class of bugs.
        kmutex (core/mutex.c) is a FOURTH bespoke user of wait_next — the sched.h
        comment only mentions tty/pipe/sd, which is already stale. The shared link
        means a task can be on at most one wait queue at a time; make the new
        primitive assert that invariant instead of silently corrupting the list.

   2. Sleeping-lock family
      Effort: M | Unlocks: scalable read-mostly structures; safe long critical sections
      Scope: rwsem, semaphore, and completion on top of the wait queue; extend
        lockdep to cover sleeping locks too.
      Done: FAT32's coarse kmutex can be split (e.g. rwsem for lookups) without
        hand-rolling anything.
      Note: kmutex (recursive sleeping mutex) already exists in core/mutex.c — build
        the family around it, don't start from scratch.

   3. preempt_count (preemption safety)
      Effort: M-L | Unlocks: a genuinely preemptive kernel (Phase 5 item 3)
      Scope: per-CPU preempt_disable/enable; the timer tick only reschedules when
        preemptible; spin_lock bumps the count.
      Done: holding a plain spinlock across a timer tick can no longer schedule.
      Note: exception_irq_handler() currently calls schedule() unconditionally on
        every timer IRQ. Non-irqsave spinlocks (fd_lock, pipe->lock, devfs_lock)
        are held with IRQs enabled — that is the latent priority-inversion hazard.

   4. Graceful out-of-memory handling
      Effort: M | Unlocks: a kernel that degrades instead of dying
      Scope: replace PANIC-on-allocation-failure with unwinding error returns;
        define an OOM policy for user allocations.
      Done: a fault-injected allocation failure returns -ENOMEM to userspace
        instead of taking down the machine.
      Note: runtime sites that must unwind: mmu alloc_table_page(),
        process_create() user-stack and kernel-stack paths, elf_load() ("ELF: Out
        of memory during loading"), sched_create_task(). Boot-time init PANICs
        (heap_init, slab_init, idle-task allocation) are fine to keep — don't
        spend effort unwinding code that runs before userspace exists.

   5. Unified buffer cache
      Effort: M-L | Unlocks: demand paging; halves cache memory
      Scope: collapse the page cache and block cache into one cache; the FS reads
        through it.
      Done: one cache layer, one writeback path, one eviction policy; FAT32 reads
        no longer populate two caches with the same bytes.
      Note: fs/pagecache.c keys on (node->ops, node->internal_info, page_index);
        driver/block.c keys on (dev, block_nr). A FAT32 read currently populates
        BOTH. Keep the pin/refcount discipline the page cache already has — pages
        handed out must not be evictable.

   6. VFS inode / dentry cache with refcounted vnodes
      Effort: M-L | Unlocks: hardlinks, safe rename, stable inode identity, perf
      Scope: cache vnodes by stable identity, refcount them, add a name cache.
      Done: opening the same file twice yields the same vnode; a directory scan
        isn't re-read from disk on every lookup.
      Note: fat32_vfs_lookup() and the procfs lookups slab_alloc a BRAND NEW vnode
        on every path resolution. This is also why the page cache had to key on the
        start cluster (and why empty files once aliased). A real inode identity
        fixes that class of problem at the root.

   7. Robust user-memory access
      Effort: S-M | Unlocks: safety once threads share an address space
      Scope: treat validate_user_buffer() as advisory; make the fault-fixup
        copy_to/from_user path the source of truth; uniform access_ok range checks.
      Done: no syscall depends on a pre-check that a concurrent unmap can invalidate.
      Note: validate_user_buffer walks the page tables then drops the lock before
        the copy — a TOCTOU that only bites once two tasks share a pgd.

   8. Panic/oops with symbolized backtrace + dmesg ring buffer
      Effort: S-M | Unlocks: debuggability; turns "it hung" into a stack trace
      Scope: walk frame pointers, resolve via the symbol table, print on panic; an
        in-memory log ring exposed as /proc/kmsg or a dmesg syscall.
      Done: a deliberate NULL deref prints a symbolized call chain.
      Note: scripts/gen_symtab.py and the two-pass build already produce a full
        kernel symbol table — the data is there, it just isn't used for unwinding.

   9. Hung-task / watchdog detector
      Effort: S | Unlocks: deadlocks surface instead of hanging silently
      Scope: periodic check for tasks blocked beyond a threshold or a core that
        stopped taking timer ticks; optionally the BCM2711 hardware watchdog.
      Done: an artificial deadlock prints a warning naming the stuck task.

  10. Per-CPU data API
      Effort: S-M | Unlocks: cleaner SMP code; prerequisite for scalable counters
      Scope: a small this_cpu()/per_cpu() abstraction.
      Note: the kernel currently uses bare `array[get_core_id()]` everywhere
        (sched_rq_lock[], core_irq_stats[], cpu_asid_gen[], lockdep held_locks[]).
        Fine at 4 cores, but it hides the intent and invites off-by-one bugs.

PHASE 3: DEVELOPER EXPERIENCE & BASIC I/O
Goal: Make Perspicua a place you can actually work in and observe.
================================================================================

   1. I/O multiplexing: select / poll
      Effort: M | Unlocks: event loops, servers, and most non-trivial ports
      Scope: per-fd readiness reporting + a poll_wait hook per driver.
      Done: a userspace program multiplexes console + a pipe without busy-waiting.
      Depends: Phase 2 item 1 (wait queue). Do not attempt before it.

   2. Core /dev nodes: /dev/null, /dev/zero, /dev/full, /dev/tty, /dev/random+urandom
      Effort: S | Unlocks: scripts, test fixtures, and anything expecting a real /dev
      Done: `cat /dev/zero | wc -c` style pipelines behave.
      Note: devfs registers "console", "fb0", and block devices ("sd0" via
        block.c) today — no /dev/null-style pseudo-devices. /dev/random needs an
        entropy source — the generic timer's low bits are a starting point.

   3. RTC / wall-clock driver
      Effort: S-M | Unlocks: real timestamps; makes gettimeofday meaningful
      Done: file mtimes and `date` survive a reboot.
      Note: get_system_time() is monotonic-since-boot only — there is no wall clock
        anywhere in the system today.

   4. Shell quality of life: globbing, history, tab completion, then scripting
      Effort: M | Unlocks: an interactive environment you don't fight
      Scope: glob (*, ?, [..]); line editing w/ history; then if/for/while, &&/||,
        subshells; job control (fg/bg/jobs) once Phase 1 item 2 lands.
      Done: a multi-line shell script runs correctly.

   5. Ramdisk block backend + tmpfs
      Effort: S-M | Unlocks: fast scratch space; deterministic FS test fixtures
      Done: /tmp is writable and FS tests run without touching the SD card.
      Note: ramfs.c and initrd.c exist but are currently unwired (no callers) —
        decide to wire them up or delete them rather than leaving dead code.

   6. Syscall tracing (strace-lite) + kernel log levels
      Effort: S-M | Unlocks: debugging userspace without a debugger
      Scope: an opt-in trace of syscall entry/exit per process; runtime log levels.
      Done: you can see why a ported program fails without adding printfs.

   7. eventfd / timerfd / signalfd
      Effort: S-M | Unlocks: clean event loops
      Depends: Phase 3 item 1 (poll).

PHASE 4: ADVANCED MEMORY & STORAGE  (the heavy lifting)
Goal: The core mechanisms that define a modern OS. Each depends on Phase 2.
================================================================================

   1. munmap / mprotect / mremap + a real VMA list
      Effort: M | Unlocks: a correct memory lifecycle; prerequisite for everything below
      Scope: track VMAs per process (base, len, prot, flags, backing); implement
        teardown and permission change.
      Done: a program can map, protect, and unmap; nothing leaks across the cycle.
      Note: SYS_MMAP exists but there is NO munmap or mprotect — mapped regions
        can never be released. The va_allocator is a bump allocator with a 64-region
        array (process_va_free exists but is only used on the mmap failure path).
        This is the most glaring memory-management gap in the kernel today.
        Budget for TLB invalidation: munmap/mprotect must broadcast-invalidate
        (TLBI ...IS by ASID) BEFORE freeing pages back to the PMM, or a stale
        entry on another core becomes a use-after-free — the same class as the
        ASID-generation aliasing bug already fixed.

   2. brk / sbrk (or an anonymous-VMA heap)
      Effort: S-M | Unlocks: a normal libc malloc
      Note: userspace malloc currently mmaps 1MB chunks and can never return them
        (no munmap), so every process's footprint only grows.

   3. Demand paging (fault-in ELF and file pages)
      Effort: L | Unlocks: fast process start, big binaries, low RAM use
      Scope: on a translation fault, resolve the VMA, fetch the page through the
        unified buffer cache, map it.
      Done: exec of a large binary maps only the pages actually touched.
      Depends: Phase 2 item 5 (unified cache), Phase 4 item 1 (VMAs).
      Note: handle_abort() already routes permission faults to COW — the
        translation-fault path is the natural hook. elf_load() currently reads every
        segment eagerly at exec time.

   4. File-backed mmap
      Effort: M | Unlocks: mmap'd I/O; a prerequisite for dynamic linking
      Note: the vnode ops table already has an ->mmap hook, SYS_MMAP already
        calls it when present, and the framebuffer ALREADY implements it (fb.c
        wires fb_mmap) — but no filesystem does. Beware: mmap of a regular-file
        fd today "succeeds" while mapping zero pages (the hook is simply absent),
        so the first access faults.

   5. Shared-memory IPC (MAP_SHARED, shm_open)
      Effort: M | Unlocks: high-performance IPC; the graphics server
      Depends: Phase 4 items 1 and 3.

   6. COW and reclaim refinements
      Effort: M | Unlocks: lower memory pressure
      Scope: skip the copy when refcount == 1; demand-zero pages; an LRU reclaim
        path under pressure; guard pages + auto-grow for user stacks.
      Note: mmu_handle_cow() always allocates and copies, even when the faulting
        process is the only owner of the page.

   7. A second, inode-based filesystem (ext2, or a small journaling FS)
      Effort: L | Unlocks: proof the VFS is generic; crash consistency
      Done: both FAT32 and the new FS mount and pass the same FS test suite.
      Note: this is the real test of the VFS abstraction — FAT32 currently stores
        its start cluster in vnode->internal_info, and the VFS has quietly shaped
        itself around that. Expect to find leaks in the abstraction.

   8. Filesystem crash consistency
      Effort: L | Unlocks: surviving power loss
      Scope: ordered metadata writes / a journal; or an fsck-lite pass at mount.
      Note: FAT32 today can cross-link clusters or corrupt a directory if it panics
        mid-write. The per-FS lock makes operations atomic against each other, not
        against a crash.

   9. Storage breadth: GPT, multiple partitions/mounts, >1GB RAM
      Effort: M | Unlocks: real hardware configurations
      Note: pmm_init() reads a SINGLE size cell from /memory@0 (reg[2]) and the MMU
        maps a fixed 4GB — so a 4GB/8GB Pi 4 is capped at 1GB usable today. Fix the
        DTB parse (honor #address-cells/#size-cells) alongside this.

PHASE 5: CONCURRENCY & SECURITY
Goal: Use the hardware fully and safely.
================================================================================

   1. Threads: clone() + TLS + per-thread state
      Effort: L | Unlocks: multi-core applications; pthreads
      Scope: multiple tasks sharing one address space and fd table; TID; TLS via
        tpidr_el0; per-thread signal mask.
      Done: a multi-threaded program measurably uses more than one core.
      Note: several structures assume ONE task per process and must be revisited:
        schedule() reads process_table[next->pid] lock-free (only safe because a
        task's process can't be exec/exit-ing itself), signal delivery targets
        p->main_task, and signal state lives on the process not the task.

   2. Futexes -> a real pthreads library
      Effort: L | Depends: Phase 2 item 1 (wait queue), Phase 4 item 5 (shm).

   3. Preemptive, priority/MLFQ scheduling + load balancing
      Effort: L | Unlocks: responsiveness under load
      Depends: Phase 2 item 3 (preempt_count).
      Note: per-core runqueues and work stealing already exist; what's missing is
        priorities, fairness, and a real balancing policy (today it's round-robin
        with an on_core guard).

   4. RCU / seqlocks for read-mostly state
      Effort: L | Unlocks: SMP scalability
      Note: the process table and mount table are read on every schedule, signal,
        and path resolution but written rarely — they will become the contention
        point once the coarse locks above are in place.

   5. Security hardening
      Effort: M-L | Unlocks: resilience against memory-corruption bugs
      Scope: W^X audit of user mappings; ASLR (stack/mmap/PIE) + user stack
        canaries; PAN/SMAP-equivalent so the kernel can't deref user pointers
        outside the uaccess helpers; KASLR later.
      Note: the kernel already sets PXN/UXN and enforces per-segment permissions —
        this is about extending the same discipline to userspace.

   6. Multi-user: uid/gid + a permission model
      Effort: L | Unlocks: login, real access control
      Note: FAT32 has no permission bits — this likely waits on Phase 4 item 7.

PHASE 6: STRATEGIC EXTENSIONS  (long-term)
Goal: Broaden into networking, graphics, and beyond.
================================================================================

   1. A real device stack: PCIe + USB host
      Effort: XL | Unlocks: networking, input, mass storage — most of Phase 6
      Note: this is the hidden prerequisite behind "add networking" on the Pi 4;
        budget for it explicitly rather than discovering it later. The current
        driver model also probes only the FIRST matching FDT node and builds a
        stack-local struct device — it needs a real device lifetime first.

   2. Network stack (NIC driver, then LWIP or a minimal UDP/IP)
      Effort: XL | Unlocks: remote access, servers
      Depends: item 1 above, Phase 3 item 1 (poll).

   3. Input stack (USB HID keyboard/mouse)
      Effort: L | Depends: item 1 above.

   4. Graphics server (Wayland-lite compositor)
      Effort: XL | Depends: Phase 4 item 5 (shm) + item 3 above (input).

   5. Dynamic linking (ld.so + shared objects)
      Effort: L | Unlocks: smaller binaries
      Depends: Phase 4 item 4 (file-backed mmap). Mostly a user-space loader
        problem; do it once there are many large binaries to justify it.

   6. POSIX ABI compatibility
      Effort: M-L | Unlocks: porting prebuilt software
      Scope: align syscall numbers and struct layouts with Linux/AArch64.

   7. Self-hosting toolchain
      Effort: XL | Unlocks: the classic milestone — build Perspicua on Perspicua.
      Note: a good forcing function; it will surface every libc and FS gap at once.

   8. Namespaces / containers, cgroup-style limits
      Effort: XL | Depends: Phase 5 item 6.

   9. Virtualization via EL2
      Effort: XL | Unlocks: running guest OSes on top of Perspicua.

  10. Power management: CPU idle states, DVFS, suspend
      Effort: L | Note: the scheduler already parks idle cores on WFE — real idle
        states and frequency scaling build from there.
